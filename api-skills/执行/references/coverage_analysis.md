# 覆盖率分析

回答三个问题：**测了什么？漏了什么？覆盖够吗？**

---

## 做 / 不做

| 做 | 不做 |
|----|------|
| API 端点覆盖率计算 | 执行测试（走 api-skills） |
| 需求→用例覆盖矩阵 | 修代码（走开发） |
| 漏测区域识别 | |

---

## API 端点覆盖率

把 OpenAPI 规范与实际测试记录对比，算出覆盖率。

### 计算方式

```
覆盖率 = 已覆盖端点数 / 总端点数 × 100%
```

### 路径归一化

```
/api/user/123  和  /api/user/456  → 视为同一个端点 /api/user/{param}
```

### 输出示例

| 端点 | 方法 | 测试次数 | 通过率 | 状态 |
|------|------|----------|--------|------|
| /api/login | POST | 10 | 100% | [OK] 已覆盖 |
| /api/products | GET | 5 | 100% | [OK] 已覆盖 |
| /api/orders | POST | 8 | 75% | [OK] 已覆盖 |
| /api/refund | POST | 0 | - | [FAIL] 未覆盖 |
| /api/inventory | GET | 0 | - | [FAIL] 未覆盖 |

```
总端点数：5
已覆盖：3
覆盖率：60%
```

## 需求→用例覆盖矩阵

从需求文档出发，逐功能点检查是否有测试用例覆盖。

### 工作流程

```
需求文档 → 功能点拆分 → 匹配测试用例 → 计算覆盖率
```

### 匹配规则

- 功能点来源：需求文档的 `feature_points` 字段
- 匹配方式：用例的「标题 + 步骤文本」是否包含功能点名称
- 噪声过滤：自动排除纯数字、纯字母、单字符

### 输出示例

| 需求 | 功能点 | 用例数 | 覆盖率 | 状态 |
|------|--------|--------|--------|------|
| 用户登录 | 正确登录 | 3 | 100% | [OK] |
| 用户登录 | 密码错误 | 2 | 100% | [OK] |
| 用户登录 | 账号锁定 | 0 | 0% | [FAIL] |
| 订单创建 | 正常下单 | 5 | 100% | [OK] |
| 订单创建 | 库存不足 | 0 | 0% | [FAIL] |

## 漏测区域识别（Gap 分析）

自动找出完全没有被测试覆盖的 API 端点，按优先级排序：

| 优先级 | 类别 | 说明 |
|--------|------|------|
| *** 高 | API | 该端点未被任何测试用例/执行记录覆盖 |
| ** 中 | 场景 | 该业务场景未被测试覆盖 |
| * 低 | 代码 | 代码文件覆盖率不足 80% |

### 输出示例

```
漏测分析：
1. [高] DELETE /api/orders/{id} - 无测试用例
2. [高] POST /api/refund - 无测试用例
3. [中] 订单取消流程 - 无场景测试
4. [低] inventory.py - 代码覆盖率 65%
```
