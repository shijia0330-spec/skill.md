# 交互式报告

测试报告不是干巴巴的文本——**能钻进去看细节**，从总览点到失败用例，再点到具体的请求和响应。

---

## 做 / 不做

| 做 | 不做 |
|----|------|
| 钻取分析：总览 → 技能 → 用例 → 请求/响应 | 执行测试（走 api-skills） |
| 对比模式：两次回归结果对比 | 生成测试数据（走 data-factory） |
| 一键报 Bug | |

---

## 报告结构

### 总览层

| 指标 | 说明 |
|------|------|
| 通过率 | 通过/总数（如 87% = 26/30） |
| 通过/失败/跳过 | 三类用例数量 |
| 执行时长 | 总耗时 |
| 自愈率 | healed 用例占比 |

### 技能层

按测试技能分组：

| 技能 | 通过 | 失败 | 跳过 |
|------|------|------|------|
| API 链式测试 | 20 | 3 | 0 |
| UI自动化 | 5 | 1 | 0 |
| 数据工厂 | 1 | 0 | 0 |

### 用例层

点击失败用例展开：

| 信息 | 说明 |
|------|------|
| 用例标题 | 用例名称 |
| 错误信息 | 失败原因 |
| 请求 URL | 接口地址 |
| 状态码 | HTTP 状态码 |
| 响应片段 | 响应体摘要 |
| 断言详情 | 期望 vs 实际 |

---

## 钻取流程

```
Reports 页面
  总览：通过率 87%（26/30）
    ↓ 点击「API 链式测试」
  技能层：3 失败 / 20 通过
    ↓ 点击「创建订单-边界值」
  用例层：
    请求：POST /orders  body: {sku: ""}
    响应：400  {"msg": "sku required"}
    断言：期望 200
    [一键报 Bug] → 预填标题和栈信息
```

**生活例子**：像医院报告——总评异常 → 点开血常规 → 看具体指标。

---

## 对比模式

勾选两份报告，查看差异：

| 对比项 | 说明 |
|--------|------|
| 新增失败 | 上次通过、这次失败的用例 |
| 已修复 | 上次失败、这次通过的用例 |
| 持续失败 | 两次都失败的用例 |
| 性能变化 | 响应时间对比 |

**生活例子**：像体检对比——今年 vs 去年哪项变差。

## 覆盖率矩阵

| 端点 | 测试次数 | 通过率 | 平均响应时间 | 状态 |
|------|----------|--------|-------------|------|
| POST /api/login | 10 | 100% | 120ms | [OK] |
| POST /api/orders | 8 | 75% | 450ms | [WARN] |
| GET /api/products | 5 | 100% | 80ms | [OK] |

## 一键报 Bug

报告内直接创建缺陷：

1. 点击失败用例的 **[一键报 Bug]**
2. 系统自动预填：
   - 标题：`POST /api/orders 返回 500`
   - 描述：请求/响应/断言详情
   - 严重级别：根据错误类型自动判定
   - 附件：失败截图/日志
3. 确认后提交到缺陷系统
