# 测试修复提示模板

**版本**: v2.0  
**用途**: 测试脚本执行失败时，提供给 AI 的修复指导模板。每种失败场景对应一个修复策略。

---

## 一、契约漂移修复

**触发条件**: 接口返回的字段结构变了，测试脚本里的断言或数据模型对不上。

**需要提供的信息**: 错误描述、当前脚本、接口实际返回

```
你是资深测试工程师。当前 pytest 脚本因为接口返回结构变化而失败，请修复脚本使其与最新接口一致。

失败信息:
{error_info}

当前测试脚本:
{test_script}

接口实际返回:
{test_result}

修复要求:
1. 调整数据模型、断言路径或解析逻辑，使其与实际返回匹配
2. 不要为了通过测试而降低验证标准（比如把精确断言改成 always_pass）
3. 只返回修复后的完整 Python 脚本，不要加任何解释文字
```

---

## 二、认证问题修复

**触发条件**: 登录失败、Token 过期、认证方式变了，导致 401/403 错误。

**需要提供的信息**: 错误描述、HTTP 状态码、认证方式、当前脚本、响应头

```
认证异常，需要修复测试脚本中的认证逻辑。

服务器返回: {error_message}
状态码: {status_code}
认证方式: {auth_type}
响应头: {response_headers}

当前测试脚本:
{test_script}

修复策略（按需选用）:
- 401 + Token 过期提示 → 添加登录刷新逻辑，检查时钟偏差
- WWW-Authenticate 头不匹配 → 调整 Basic/Bearer/API Key 的放置位置
- 403 权限不足 → 检查用户角色和权限范围
- 只返回修复后的完整脚本，不要加解释
```

---

## 三、路由变更修复

**触发条件**: 接口路径变了（比如 `/api/v1/` 改成 `/api/v2/`），导致 404 或重定向。

**需要提供的信息**: 错误描述、当前脚本

```
接口路径或基础地址发生变化，测试脚本中的 URL 需要更新。

错误信息: {error_info}

当前测试脚本:
{test_script}

修复要求:
1. 更新 URL 组成（主机地址、路径前缀、版本号）
2. 保持幂等性和超时设置不变
3. 只返回修复后的完整脚本
```

---

## 四、断言滞后修复

**触发条件**: 接口行为变了（产品迭代或 bug 修复），但测试断言还按旧逻辑判断。

**需要提供的信息**: 错误描述、当前脚本、接口实际返回

```
测试断言与实际接口行为不一致，可能是产品逻辑已更新。

错误信息: {error_info}

当前测试脚本:
{test_script}

接口实际返回:
{test_result}

修复要求:
1. 判断是产品逻辑变了还是接口真有 bug
2. 如果是产品逻辑变了，更新断言使其与新逻辑一致
3. 对不应变化的字段保持严格验证
4. 只返回修复后的完整脚本
```

---

## 五、数据约束修复

**触发条件**: 测试数据不符合接口要求，导致 400/422 错误。

**需要提供的信息**: 错误描述、当前脚本

```
测试数据违反接口约束，需要修正数据构造逻辑。

错误信息: {error_info}

当前测试脚本:
{test_script}

修复要求:
1. 修正数据工厂或 fixture 中的数据生成逻辑
2. 遵守字段间关联规则（比如 A 字段为 X 时 B 字段必填）
3. 随机数据加命名空间避免冲突
4. 只返回修复后的完整脚本
```

---

## 六、业务逻辑更新修复

**触发条件**: 业务流程顺序变了（比如先支付后创建订单变成先创建订单后支付），测试步骤需要调整。

**需要提供的信息**: 错误描述、当前脚本

```
业务流程或状态机发生变化，测试步骤顺序需要调整。

错误信息: {error_info}

当前测试脚本:
{test_script}

修复要求:
1. 重新排列等待、操作、断言的顺序
2. 如有必要，在关键位置加一行注释说明变更原因
3. 只返回修复后的完整脚本
```
