# PRD 与技术文档双轨合并

分析阶段把 **业务意图（PRD）** 和 **实现约束（技术文档）** 对齐，避免方案和计划各说各话。

---

## 1. 合并表（复制填写）

| # | PRD 条目（业务） | 技术映射（实现） | 测试关注点 | 优先级 | 缺口 |
|---|------------------|------------------|------------|--------|------|
| 1 | | | | P0/P1/P2 | T-xx / 无 |
| 2 | | | | | |

**填写规则**：

- PRD 有条目、技术文档无实现 → 缺口列 `T-xx`，owner 开发。  
- 技术文档有接口、PRD 无业务描述 → 缺口列 `T-xx`，owner 产品。  
- 两边都有但不一致 → 缺口列「冲突」，进待澄清清单。

---

## 2. PRD 轨 — 从简陋 PRD 能抠啥

| PRD 常见形态 | 可提取 | 常缺 |
|--------------|--------|------|
| 功能列表 | 模块、In-Scope 候选 | 验收标准、边界 |
| 用户故事 | 角色、主流程 | 异常、权限细节 |
| 原型/截图 | UI 范围 | 接口、数据规则 |
| 一句话需求 | 模块名 | 几乎一切 |

**不要编造**：PRD 没写的数字（超时、限额、并发）标 `T-xx`，方案和计划里占位。

---

## 3. 技术文档轨 — 常见章节映射

| 技术文档章节 | 对方案/计划的价值 |
|--------------|-------------------|
| 架构图 | 集成测试范围、环境依赖 |
| 接口设计 / OpenAPI | API 测试范围、联调顺序 |
| 数据模型 | 测试数据策略 |
| 中间件（Redis/MQ） | 专项策略、环境要求 |
| 部署 / 环境 | REST 测试环境拓扑 |
| 非功能（性能/安全） | 是否单测性能/安全、工具选型 |

## 4. 对照示例（财务 v1.1）

| PRD 条目 | 技术映射 | 测试关注点 | 缺口 |
|----------|----------|------------|------|
| admin 配置活动 | `POST /admin//activities` | 权限、状态 UPCOMING | 无 |
| 活动开始前不可下单 | 服务层校验 `start_time` | 时间边界 | T-03 时区以谁为准 |
| developer 下单 | `POST //orders` + Redis | 主路径、防超卖 | 无 |
| 每人限购 | （未在技术文档找到） | 并发限购 | T-01 |
| Redis 预热库存 | `POST .../prepare-stock` | 预热失败、重复预热 | 无 |
