# 准入 / 准出标准 — 写法规范

方案和计划中的 **准入**（测试能否开始）、**准出**（测试能否结束）必须 **可观测**，禁止模糊表述。

---

## 1. 禁止 vs 推荐

| 禁止 | 推荐 |
|------|------|
| 测试差不多完成 | P0 缺陷 = 0，P1 无阻塞项 |
| 主要功能没问题 | In-Scope §3.2 策略表全部执行并有记录 |
| 性能还可以 | 下单接口 P99 < T-xx ms（或「抽样 50 并发无超卖」） |
| 环境准备好了 | test 环境 Redis/MySQL 连通；`GET /health` 200 |

---

## 2. 测试活动准入（方案 §6）

至少包含以下 **可勾选** 项（按项目裁剪）：

```markdown
## 准入标准

- [ ] **范围**：In-Scope 已评审；T-xx 清单已 @ 相关 Owner
- [ ] **环境**：REST 测试环境部署完成；依赖服务清单可用（MySQL __ / Redis __）
- [ ] **构建**：待测版本号 __ 已部署到 test
- [ ] **数据**：测试账号与基础数据就绪（见 §5.3）
- [ ] **开发自测**：阻塞级缺陷已关闭或已登记豁免（编号：__）
- [ ] **文档**：接口文档/OpenAPI 与部署包版本一致（或已知差异 T-xx）
```

**闸门**：准入未满足项 >2 且均为阻塞 → 计划 Skill 不得排「执行阶段」起始。

---

## 3. 测试活动准出（方案 §7）

```markdown
## 准出标准

- [ ] **覆盖**：方案 §3.2 各模块策略已执行（附测试记录/用例批/执行报告链接）
- [ ] **缺陷**：P0 = 0；P1 ≤ __ 或全部有豁免；无未评估阻塞缺陷
- [ ] **自动化**：（若适用）`pytest tests/_api_smoke` 全绿
- [ ] **回归**：（若 In-Scope）回归批 __ 已执行
- [ ] **评审**：`testplan-skills/评审` 方案+计划+（若有）用例评审签字
- [ ] **待澄清**：T-xx 未关闭项不影响准出 / 已豁免（说明：__）
```

---

## 4. 环境级准入（环境就绪）

| 检查项 | 验证方式 |
|--------|----------|
| API 可达 | `curl http://host:5000/health` → 200 |
| MySQL | 连接成功；迁移版本 = __ |
| Redis | `PING` → PONG； key 可写 |
| 账号 | admin/developer 各至少 1 个可用 |

---

## 5. 里程碑级准出（供计划 Skill 引用）

每个里程碑一行 **退出准则**：

| 里程碑 | 退出准则（可观测） |
|--------|-------------------|
| W1 认证冒烟 | 注册/登录/401 用例或 API 冒烟全绿 |
| W2 预热 | prepare-stock 在 Redis 可用时 200 |
| W3 下单主路径 | 单用户 ACTIVE 下单成功；限购用例批完成 |
| W4 发布 | P0=0 + 评审签字 |

---

## 6. T-xx 与准出的关系

| 情况 | 准出写法 |
|------|----------|
| T-xx 不影响已写策略 | 准出照常；附录列出未关闭 T-xx |
| T-xx 阻塞准出条（如限购 N） | 该条目标「待 T-01 确认后生效」；整体准出标 **有条件** |
| 产品书面豁免 | 准出附豁免编号与签字 |

---

## 7. 分阶段准出（多模块 / 大用例库项目）

源 PRD/Excel 常不写「哪一里程碑卡质量指标」。方案须 **至少两套** 准出（M1 联调 + M4 SLT），并列出 **M1 非阻塞项**。

| 类型 | 写法 |
|------|------|
| M1 成功口径 | P0 主路径 + N×E2E + P0=0 + collect-only |
| M1 非阻塞 | 秒杀压测、财务对账深度、长稳 — 抽样不卡 M1 |
| M4 硬性 | T-03/T-04/T-05/T-15 等，见附录 A.1 |

完整模板：`staged_exit_criteria.md`。  
**测试扩展**的分层准出须在 §4.2 或附录 H 标来源，评审时与产品对齐。

---

## 8. 与 testcase-skills 对齐

- 准出「覆盖」可指向 `output/*_testcases.md` 执行率。  
- 自动化准出与 `api-skills/执行` 状态码断言一致。  
- M1 自动化可用 **collect-only ≥N** 代替全绿（OpenAPI 未定时）。
