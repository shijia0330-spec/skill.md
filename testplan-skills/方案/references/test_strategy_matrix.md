# 测试策略矩阵 — 模块 × 类型

方案 Skill **Step 3** 使用。根据 **风险优先级** 和 **变更范围** 决定每种测试做不做、做多深。

---

## 1. 深度档位

| 档位 | 含义 | 典型工作量 |
|------|------|------------|
| **L0** | 不测 / 仅冒烟一句 | 0.5d 内 |
| **L1** | 主路径 Happy Path | 1～2d |
| **L2** | 主路径 + 关键异常 + 边界 | 3～5d |
| **L3** | L2 + 集成/并发/安全抽查 | 1 周+ |
| **T-xx** | 待澄清，方案中占位 | — |

---

## 2. 测试类型说明

| 类型 | 何时必做 | 何时可砍 |
|------|----------|----------|
| **功能** | 所有 In-Scope 模块 | 无 |
| **接口** | 有 HTTP/RPC 文档 | 纯 UI 且无 API |
| **集成** | 跨服务/中间件 | 单体内聚模块 |
| **回归** | 改动影响老功能 | 全新独立服务 |
| **性能** | PRD/技术有 SLA 或交易高峰 | 内部工具、无 SLA |
| **安全** | 对外、权限、资金 | 纯只读内部报表 |
| **兼容** | 多端/多浏览器要求 | 仅 API 无 UI |

---

## 3. 决策表（风险 × 模块）

先给模块标 **P0 / P1 / P2**（来自分析 `risks` 或 `testcase-skills/规划` 评分）。

| 模块优先级 | 功能 | 接口 | 集成 | 回归 | 性能 | 安全 |
|------------|------|------|------|------|------|------|
| **P0** | L2～L3 | L2 | L2 | L1～L2 | 抽样或 T-xx | L1～L2 |
| **P1** | L1～L2 | L1 | L1 | L1 | — 或抽样 | L1 |
| **P2** | L0～L1 | L0～L1 | — | L0 | — | — |
| **Out-of-Scope** | — | — | — | — | — | — |

## 4. 技术文档触发的专项

| 技术文档出现 | 建议策略 |
|--------------|----------|
| Redis / 缓存 | 集成 L2 + 故障注入（若 T-xx 则占位） |
| 消息队列 | 集成 + 重复消费/丢失（抽样） |
| 支付/资金 | 功能 L3 + 安全 L2 |
| JWT / RBAC | 接口 L2 + 安全 L2（越权） |
| 定时任务 / 状态机 | 功能 L2 + 时间边界 |
| OpenAPI | 接口 L2；可对接 `api-skills` 自动化 |
