# UI 自动化跑完 — 脚本放哪、报告留啥

约定 **Python + pytest-playwright** 这批交付物；和 API 那条线的报告字段不是一回事，别混着用。

---

## 1. 交付物一般长啥样

| 东西 | 建议 |
|------|------|
| 脚本 | `tests/` 或 `output/` 里 `test_*.py`，pytest 能搜到 |
| 说明 | 模块 docstring 写一句业务背景 |
| 依赖 | `requirements.txt` 或 lock 文件能复现 |

默认 **不要**交 `.spec.ts` 当主线；历史项目另说。

---

## 2. 用例编号

搞一个固定格式（例如 `TC-UI-001`），pytest 里用注释或 marker 挂上。后面扯缺陷、对报告，都靠这个串。

---

## 3. 怎么跑（最小集）

环境变量至少：**TEST_BASE_URL**；账号 **TEST_USERNAME** / **TEST_PASSWORD**；可选 **UI_STORAGE_STATE**。

**Windows 推荐**（包根目录，trace + 失败截图 + Allure）：

```powershell
$env:TEST_BASE_URL = "http://your-server:5001"
$env:TEST_USERNAME = "admin"
$env:TEST_PASSWORD = "admin123"
$env:UI_STORAGE_STATE = "output/.auth/ui_storage.json"
python3 UI-skills/执行/scripts/save_ui_storage_state.py   # 首次可选
python3 codegen/run_spec.py templates/ui_smoke_one_page.md -o output/ui_smoke_one_page.py
powershell -File run_pytest_ui.ps1 output/ui_smoke_one_page.py -v --headed
# Allure 默认 → output/allure-report/standalone.html（关闭：-NoAllure 或 ALLURE=0）
```

> UI 脚本依赖 `codegen/ui_lib`，请在**包根目录**执行 pytest，不要 `cd output` 后再跑。

**Linux / 通用**：

```bash
export TEST_BASE_URL=http://your-server:5001
export PYTHONPATH=codegen
pytest output/ui_smoke_one_page.py -v --tracing=retain-on-failure --screenshot=only-on-failure
python3 scripts/allure_fallback_report.py output/allure-results output/allure-report/standalone.html
```

根目录 `conftest.py` 会在 UI 失败时额外写 **PNG + HTML** 到 `output/ui_artifacts/`。

---

## 4. 报告与附件

| 用途 | 常见产物 |
|------|----------|
| 人看 | Allure standalone / Playwright HTML / pytest-html |
| 门禁扫 | JUnit XML |
| 查 flaky / 定位失败 | trace.zip |
| 报 bug | 截图或短视频 |

群里同步失败时，最少带上：**脚本路径、报告链接、失败用例号、trace 路径**。

---

## 5. 红了之后

先分清环境 flake 还是稳定复现；定位问题按 **稳定属性 → 范围收紧 → 最后才视觉**；真是产品 bug 走 **bug-reporter**；脚本过时走 **自我修复**。

**pytest 失败时**：自动写 **`output/bugs/BUG-*.md`** 草稿（见 `bug-reporter/SKILL.md` § pytest）。UI 失败草稿会标「界面」类并建议先走 **自我修复**。
