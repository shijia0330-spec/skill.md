# 拼「分析摘要」给代码生成用

**代码参考**：`playwright_script_generator_agent` / `_prepare_analysis_summary()`。

代码生成不能只吃一句「帮我测登录」，要把 **人想验啥** 和 **页面上有啥控件线索** 拼到一块儿。这篇约定拼装的块和顺序。

---

## 1. 为啥要拼

模型只知道一句话时，容易瞎编选择器。摘要里同时给：

- **验收话**：用户想证明什么；  
- **可选控件表**：分析阶段如果有 `elements` / `database_elements`，把稳定属性带上。

默认栈是 **Python pytest-playwright**，摘要里别夹「输出 TypeScript / MidScene」那种和本仓库打架的话。

---

## 2. 三块内容（从上到下）

**第一块 — 验收意图（必填）**  
来自 `main_content` 或用户粘贴的步骤。标题可以叫「验收意图」，里面贴原文，有账号、数据前提一并写上。

**第二块 — 页面控件（有就写）**  
有分析结果再拼；没有整段省略，别塞「待补充」占位糊弄。列：控件含义、推荐 testid/role、是不是在弹窗里、可信度。

**第三块 — 生成约束（固定尾巴）**  
写死几条：Python + pytest + Playwright 同步 API；定位先 L1；断言用 `expect`；需要时 `wait_for_response`；秘钥走环境变量。

---

## 3. 拼完长什么样（逻辑顺序）

```
[验收意图]
空行
[控件表，可选]
空行
[生成约束]
```

结果塞进用户任务模板的 **`{analysis_summary}`**。

---

## 4. 数据从哪来

| 字段 | 常见来源 |
|------|----------|
| 验收话 | `main_content` |
| 控件 | `database_elements` / `elements` |

---

## 5. 注意

- 没有 `main_content` 就别生成代码，先回去问用户。  
- 控件信息全是低置信度时，摘要里写明「需手工确认」，避免模型自信乱点。

---

## 6. 调用链（备忘）

准备生成任务 → 拼摘要 → 填 `02_Playwright代码生成_用户任务模板.md` → 出 `test_*.py` → 评审 → CI。
