# 自然语言一句话 UI 执行

用户**用口语描述要在秒杀财务系统（或其它已配置前端）上做的事**，不要手写 Playwright 脚本，也不要写死业务流程模板。

## 执行方式（按优先级）

### 1. 对话页（推荐演示）

```bash
# 终端 1：你的业务前端（示例）
cd <你的业务系统根目录> && python3 run.py

# 终端 2：自然语言 UI 服务（若你单独提供 nl_api_server 包）
cd <NL服务代码目录> && python3 nl_api_server.py
# 或仅配置 NL_API_URL 指向已启动的服务
```

浏览器打开：**http://your-server:5010/** ，在输入框说一句话即可。

### 2. HTTP API

```bash
curl -s -X POST http://your-server:5010/api/nl/run \
  -H 'Content-Type: application/json' \
  -d '{"text":"给我新增一个商品，名字叫演示A"}'
```

仅拆分、不跑浏览器：

```bash
curl -s -X POST http://your-server:5010/api/nl/parse \
  -H 'Content-Type: application/json' \
  -d '{"text":"登录后进商品页"}'
```

### 3. Skills 桥接脚本（AI Agent 可直接调用）

```bash
cd skills-专业版V3.0
python3 nl_ui_client.py "给我新增一个商品" --json
```

环境变量：

| 变量 | 说明 |
|------|------|
| `NL_API_URL` | 默认 `http://your-server:5010` |
| `DASHSCOPE_API_KEY` / `OPENAI_API_KEY` | LLM 拆分 |
| `NL_PARSER` | `auto` \| `llm` \| `regex` |
| `SECKILL_APP_ROOT` | 业务系统目录，供扫描页面控件 |

## Agent 行为规范

1. 用户说「在系统上…」「一句话…」「帮我点页面…」→ 调用 `nl_ui_client.py` 或 `POST /api/nl/run`，**不要**临时写一长串 pytest。
2. 执行前确认业务系统已启动（`GET /api/health` 中 `seckill_running: true`）。
3. 将 API 返回的 `steps_parsed` 与 `step_results` 简要反馈给用户；`success: false` 时展示失败步骤的 `error`。
4. 需要只看拆分结果时用 `--parse-only` 或 `/api/nl/parse`。

## 架构（不写死业务）

```
用户一句话 → llm_step_parser（LLM + ui_catalog 页面扫描）
          → nl_executor（通用 navigate/input/fill/click/verify）
          → 真实浏览器 → 业务系统 API/数据库
```

## 相关代码路径

- NL 服务侧（由使用方部署）：`nl_api_server.py`、`llm_step_parser.py` 等
- 本包桥接：`skills-专业版V3.0/nl_ui_client.py`（优先 `NL_API_URL`；本地回退需 `NL_PLAYWRIGHT_CODE`）
