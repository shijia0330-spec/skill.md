# 风险评估矩阵

## 1. 风险评分标准

### 1.1 概率评分

| 等级 | 分数 | 说明 |
|------|------|------|
| 极高 | 5 | 几乎肯定会发生（>80%） |
| 高 | 4 | 很可能发生（60%-80%） |
| 中 | 3 | 可能发生（40%-60%） |
| 低 | 2 | 不太可能发生（20%-40%） |
| 极低 | 1 | 几乎不可能发生（<20%） |

### 1.2 影响评分

| 等级 | 分数 | 说明 |
|------|------|------|
| 极高 | 5 | 项目失败，无法上线 |
| 高 | 4 | 严重影响进度或质量 |
| 中 | 3 | 影响部分功能或进度 |
| 低 | 2 | 轻微影响，可接受 |
| 极低 | 1 | 几乎无影响 |

### 1.3 风险值计算

```
风险值 = 概率 × 影响
```

| 风险值 | 等级 | 处理方式 |
|--------|------|----------|
| 15-25 | 极高 | 立即处理，必须有缓解措施 |
| 10-14 | 高 | 优先处理，制定应对计划 |
| 6-9 | 中 | 关注并监控，准备应急预案 |
| 1-5 | 低 | 记录并定期 review |

## 3. 风险应对策略

### 3.1 规避（Avoid）

- 修改计划，消除风险源
- 例：需求不清晰 → 推迟测试，先澄清需求

### 3.2 转移（Transfer）

- 将风险转移给第三方
- 例：第三方依赖 → 签 SLA，违约赔偿

### 3.3 缓解（Mitigate）

- 降低概率或影响
- 例：性能不达标 → 提前性能测试，优化方案

### 3.4 接受（Accept）

- 风险值低，主动接受
- 例：轻微 UI 问题 → 记录，后续迭代修复

|------|--------|--------|------|
| 用例执行率 | 100% | < 80% | 测试进度 |
