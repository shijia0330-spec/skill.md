# 测试方案与测试计划生成器

**什么时候用**：项目启动时、版本发布前、多团队协作时，需要一份完整的测试方案和计划。

**它不干什么**：不写具体测试用例，不做测试执行，只做「测什么、怎么测、谁来做、何时做完」。

---

## 1. 测试方案（Test Plan）

### 1.1 测试范围

**In-Scope**：
- 功能模块清单（列出本轮测试的功能）
- 接口清单（API 测试范围）
- 性能要求（并发量、响应时间、吞吐量）
- 安全要求（权限、加密、合规）
- 兼容性要求（浏览器、操作系统、设备）

**Out-of-Scope**：
- 不测试的功能模块
- 不覆盖的场景
- 依赖外部团队的部分

### 1.2 测试策略

| 测试类型 | 策略 | 工具 | 负责人 |
|---------|------|------|--------|
| 功能测试 | 场景法 + 等价类 + 边界值 | pytest / 手工 | |
| 接口测试 | 契约驱动 + 自动化回归 | pytest + requests | |
| 性能测试 | 基准 + 负载 + 压力 + 稳定性 | JMeter / Locust | |
| 安全测试 | 权限越权 + SQL 注入 + XSS | OWASP ZAP / 手工 | |
| UI 测试 | 关键路径自动化 | Playwright | |
| 兼容性测试 | 主流浏览器 + 移动端 | BrowserStack / 真机 | |

### 1.3 测试环境

| 环境 | 用途 | 配置 | 责任人 |
|------|------|------|--------|
| 开发环境 | 开发自测 | 本地 / Docker | 开发 |
| 测试环境 | 功能测试 | 独立服务器 | 测试 |
| 预发环境 | 回归验证 | 生产镜像 | 运维 |
| 生产环境 | 监控 | 生产集群 | 运维 |

### 1.4 测试资源

**人力资源**：
- 测试工程师：X 人
- SDET：X 人
- 开发配合：X 人
- 运维支持：X 人

**工具资源**：
- 测试管理工具：Jira / 禅道
- 自动化框架：pytest + Playwright
- 性能测试工具：JMeter / Locust
- CI/CD：Jenkins / GitLab CI

### 1.5 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 需求变更频繁 | 高 | 高 | 冻结需求基线，变更走评审 |
| 环境不稳定 | 中 | 高 | 提前搭建，每日巡检 |
| 数据准备不足 | 中 | 中 | 提前造数据，自动化生成 |
| 第三方依赖延迟 | 低 | 高 | Mock 服务，提前联调 |

### 2.1 里程碑

| 阶段 | 开始日期 | 结束日期 | 交付物 | 退出准则 |

## 3. 输出格式

### 3.1 Markdown 格式（默认）

直接输出上述表格和文本，适合 AI 编辑器直接生成。

### 3.2 Excel 格式

生成两个 Sheet：
- Sheet 1: 测试方案（范围、策略、环境、资源、风险）
- Sheet 2: 测试计划（里程碑、进度、资源分配）

### 3.3 协作文档

#### 钉钉

适配钉钉文档格式，支持直接粘贴到钉钉。

#### 飞书

适配飞书文档 / 多维表格：

- 测试方案：范围、策略、环境、风险 → 飞书 Doc 标题层级
- 测试计划：里程碑表格可直接粘贴到飞书 Sheet
- 架构说明：`STRUCTURE.md`；可视化 HTML 随交付包版本提供（若有 `architecture.html` 则浏览器打开）

## 4. 使用示例

### 示例 1：生成测试方案

```
用户：帮我生成一个电商秒杀系统的测试方案

AI：加载 test-plan/SKILL.md
    根据秒杀系统特点，生成：
    - In-Scope：秒杀活动配置、商品库存、下单流程、支付流程
    - Out-of-Scope：用户注册、商品评价
    - 测试策略：功能 60% / 性能 25% / 安全 10% / 兼容 5%
    - 环境：测试环境 + 预发环境
    - 风险：Redis 防超卖、高并发下单、支付超时
```

### 示例 2：生成测试计划

```
用户：帮我排一个 5 周的测试计划

AI：加载 test-plan/SKILL.md
    生成：
    - W1: 需求分析 + 测试设计
    - W2: 第一轮测试执行
    - W3: 第二轮测试执行
    - W4: 回归 + 性能
    - W5: 验收 + 上线
```

## 5. 与 testcase-skills/规划 的区别

| 维度 | test-plan（本 Skill） | testcase-skills/规划 |
|------|----------------------|---------------------|
| 定位 | 完整测试方案 + 计划 | 测试范围 + 策略 + 节奏 |
| 输出 | Markdown/Excel | Markdown |
| 粒度 | 项目级（多模块、多团队） | 模块级（单个功能） |
| 包含 | 环境、资源、风险、进度 | 范围、风险、里程碑 |
| 适用 | 大型项目、跨团队协作 | 小型迭代、单团队 |

---

## 6. 出口闸门

- 测试范围未明确 → **禁止**进入用例设计
- 测试策略未定义 → **禁止**开始测试执行
- 资源未到位 → **禁止**承诺上线日期
- 风险未评估 → **禁止**跳过缓解措施
