# SPA 截图限制与补拍策略

## 限制

### 1. 动态路由
SPA 路由由前端 JS 控制，爬虫无法通过静态 HTML 发现所有路由。
**解法**：手动维护路由清单（routes.txt），或从侧栏菜单提取。

### 2. 权限控制
不同角色看到不同页面。
**解法**：分角色运行，每个角色一个 storage-state，输出到不同子目录。

### 3. Tab / 抽屉 / 弹窗
这些不在 URL 中体现，BFS 爬取无法覆盖。
**解法**：使用 `--capture-dialogs` 自动截取弹窗区域。

### 4. 懒加载
页面内容按需加载，默认 wait-ms 可能不够。
**解法**：增大 `--wait-ms` 或使用 `--ready-selector` 指定就绪选择器。

### 5. 分页 / 列表
列表页只截第一页。
**解法**：在 routes.txt 中列出关键查询参数，如 `/users?page=1`。

## 补拍策略

1. **先跑 20 页验证**：确认登录态和渲染正常，再扩大规模
2. **查看 manifest.json**：检查 failed 页面，分析原因
3. **手动补拍**：对有问题的页面单独运行截图
4. **调整 wait-ms**：渲染慢的页面增加等待时间
5. **使用 headed 模式**：调试时开有头浏览器观察页面状态
