# 核心流程指南

> 下文示例均基于 **电商秒杀与财务一体化系统**（`seckill_finance_system`）：认证、商品、秒杀下单、管理端配置等。勿套用 KYC、Waitlist 等与本项目无关的场景。

## 什么是核心流程

**端到端业务路径**，有明确起点、终点和业务目标；粒度 **中等（约 10～15 个主步骤）**，用树形缩进 Markdown 表达分支。

| 对比项 | 核心流程 | 详细功能点 |
|--------|----------|------------|
| 视角 | 用户旅程 | 功能实现细节 |
| 用途 | 冒烟/主路径用例、自动化骨架 | 全量测试点 |

## 何时拆成多条流程

**应拆分**：

- 不同业务目标（**customer 秒杀下单成功** vs **admin 创建秒杀活动并预热库存**）
- 不同终态（下单成功 vs 库存不足 vs 活动未开始）
- 互斥路径（已登录 admin 操作 vs 匿名仅浏览商品列表）
- 独立测试数据与前置完全不同（Redis 已预热 vs 未预热）

**不拆分**：

- 同一登录目标下的错误密码重试、Token 过期后重新登录
- 商品创建时「仅填必填」与「含秒杀字段」两种填法
- 可选步骤（跳过非必填描述）

## 粒度示例

**[FAIL] 过粗：** 用户登录 → 参与秒杀 → 完成

**[FAIL] 过细：** 点击用户名输入框 → 输入第 1 个字符 → …

**[OK] 适中（customer 秒杀下单）：**

```markdown
### 流程1：普通用户参与进行中的秒杀并下单
- 访客浏览在售商品列表（GET /api/products，匿名）
  - 用户注册或已有账号登录（POST /api/auth/login，获得 JWT）
    - 查看秒杀活动列表，选择进行中的活动
      - 确认活动商品状态与秒杀价（GET /api/seckill/status/{activity_id}/{product_id}）
        - 提交秒杀下单（POST /api/seckill/{activity_id}/{product_id}）
          - Redis 库存扣减成功、订单创建为 pending
            - 可查询订单详情（GET /api/seckill/order/{order_id}）
          - 库存不足或活动未开始
            - 返回约定错误码，不产生有效订单
        - 已达限购次数
          - 拒绝下单并提示限购规则
```

**[OK] 适中（admin 配置秒杀）：**

```markdown
### 流程2：管理员配置秒杀活动并预热库存
- 管理员登录（admin，JWT）
  - 创建或选择秒杀活动（POST /api/seckill/activities）
    - 关联商品并设置秒杀价、秒杀库存、限购（POST .../products）
      - 调用预热接口写入 Redis（POST .../prepare-stock）
        - 预热成功，状态接口可见 Redis 库存
      - Redis 不可用
        - 返回明确错误，不误导为「预热成功」
```

## 呈现格式

```markdown
## 核心流程

### 流程1：[名称]
- 主步骤
  - 条件或分支
    - 子结果
```

缩进表示层级，**不要**用「流程1-步骤1-子步骤1」无意义编号替代语义。

## 与测试用例的关系（Step 2）

- **一条核心流程 → 测试用例中一个 `### 流程N` 块**
- 正文 **保持与 func_list 相同的树形结构**，便于对照
- 不在此层写按钮颜色等 UI 细枝末节；接口路径可与 PRD / `openapi.yaml` 对齐

## 反模式：合并多条业务目标

[FAIL] 把「admin 建活动 + customer 下单 + 财务记账 + 采购入库」塞进一条巨型流程。

[OK] 拆为例如：

- 流程1：customer 秒杀下单成功（主路径）
- 流程2：admin 活动配置与库存预热
- 流程3：秒杀失败分支（未开始 / 售罄 / 超限购）
- 流程4：匿名浏览商品列表（无登录）

财务凭证、采购销售等 **另文档另流程**，除非 PRD 明确要求同轮端到端。
