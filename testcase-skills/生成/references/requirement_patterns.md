# 常见需求模式与拆法

> 示例默认对应 **秒杀财务系统** PRD（`seckill_finance_system/需求文档.md`）。

分析 PRD 时按模式套用，输出统一为「条件 + 预期」列表，再转为检查点。

---

## 模式 1：校验类功能点

**特征**：格式、长度、唯一性、必填。

```markdown
### 商品名称校验
- 输入合法名称「秒杀演示商品A」
  - 预期：校验通过，可提交
- 名称为空或全空白
  - 预期：拒绝，提示名称不能为空
- 名称超长（超过 PRD 规定上限，如 50 字符）
  - 预期：前端限制或后端返回长度错误
```

---

## 模式 2：状态/条件类功能点

**特征**：不同状态下 UI 或接口行为不同。

```markdown
### 秒杀活动状态与下单入口
- 活动状态 UPCOMING（未开始）
  - 预期：customer 下单被拒绝，提示活动未开始（或等价）
- 活动状态 ACTIVE（进行中）且 Redis 有库存
  - 预期：允许下单，库存扣减
- 活动状态 ENDED（已结束）
  - 预期：下单被拒绝，恢复常规购买逻辑（以 PRD 为准）
```

---

## 模式 3：配置/开关类功能点

**特征**：同一功能在不同配置下行为不同；标题中注明配置名。

```markdown
### 商品列表（仅展示 active）

- 库中同时存在 active 与 inactive 商品
  - 预期：GET /api/products 仅返回 active

### 商品创建（含秒杀库存 >0）

- 管理员提交 seckill_stock=10
  - 预期：创建成功并触发秒杀准备（Redis 预热，环境具备时可观测）
- 管理员提交 seckill_stock=0
  - 预期：创建成功但不触发预热（与 PRD 一致）
```

---

## 模式 4：边界/数值类

与 `boundary_value_testing.md` 联用，每个阈值拆 trio（价格、库存、限购次数等）。

---

## 模式 5：多步骤流程

**特征**：有顺序依赖；检查点可写多 bullet。

```markdown
#### 管理员新增含秒杀且秒杀库存 >0
- 管理员已登录，POST /api/products 填写 name、price、seckill_stock=10
- 响应 201，商品状态为在售
- POST /api/seckill/activities/{id}/prepare-stock 成功（Redis 可用时）
```

---

## 模式 6：权限/角色

```markdown
#### 非管理员无法新增商品
- customer 已登录，POST /api/products
  - 预期：403

#### 匿名无法新增
- 未带 Token POST /api/products
  - 预期：401
```

---

## 模式 7：错误处理与提示

```markdown
#### 校验失败提示可理解
- 提交价格为 -1
  - 预期：400 且错误信息指明 price 字段，响应体无堆栈
```

---

## 模式 8：列表/查询类

```markdown
### 仅展示在售商品
- 库中同时在售（active）与已下架（inactive）
  - 预期：列表仅含 active

### 秒杀活动列表
- 存在 UPCOMING、ACTIVE、ENDED 多条活动
  - 预期：列表字段含活动名、时间窗、状态（与 PRD 一致）
```

| admin/customer | 6 |
