# 交付标准

> 示例项目：**秒杀财务系统**；样例文档见 `templates/测试用例-需求文档.md`、`examples/output_seckill_auth_testcases.md`。

对外交付或入库前，测试用例文档须符合本标准（与 `templates/测试用例-需求文档.md` 可对齐）。

---

## 1. 文档头（必填）

```markdown
# [模块名] 测试用例

## 文档信息
- 依据需求：[文件名/版本/链接]
- 生成版本：规则 1.2.0（skills V3.0 · testcase-skills/生成）
- RAG 检索：有命中 N 条 / 无命中（检索词：…）
- 测试范围：[一句话]
- 结构说明：[2/3/4 级层级]
- 待澄清汇总：[条数，或「无」]

## 知识库检索摘要

（Step 0a 输出；引用 [case]/[bug]/[best_practice] 须在追溯表或检查点标注来源）
```

---

## 2. 用例编号（专业版必填）

| 前缀 | 含义 | 示例 |
|------|------|------|
| F- | 核心流程 | F-01 |
| L- | 列表/查询 | L-01 |
| D- | 详情/单条读 | D-01 |
| C- | 创建/新增 | C-01 |
| U- | 更新/编辑 | U-01 |
| X- | 删除/作废 | X-01 |
| V- | 校验/边界 | V-01 |
| P- | 权限/安全 | P-01 |
| N- | 非功能 | N-01 |
| T- | 待澄清占位 | T-01 |

格式：`{前缀}-{两位序号}`，在检查点标题或评审表中出现。

---

## 3. 优先级

| 级别 | 定义 | 建议占比 |
|------|------|----------|
| P0 | 核心流程、资金/权限、数据丢失风险 | ≤20% |
| P1 | 主功能正向与关键异常 | ~40% |
| P2 | 边界、次要场景 | ~30% |
| P3 | 低概率、体验类 | ≤10% |

每条 **评审表** 行须带优先级；Markdown 检查点可在 `####` 后注释 `<!-- P0 -->` 或单独附评审表章节。

```markdown

## 待澄清清单（专业版）
```

### 4.1 需求追溯表

| 需求段落/标题 | 用例编号范围 | 覆盖说明 |
|---------------|--------------|----------|

### 4.2 用例评审表（简表）

| 编号 | 名称 | 优先级 | 类型 | 标签 |
|------|------|--------|------|------|
| L-01 | … | P0 | functional | module,list |

类型建议：`smoke_sanity` | `functional` | `regression` | `boundary` | `security` | `integration` | `pending_clarification`

### 4.2.1 页面路径（Web / 有 UI 的模块 · 必填）

**Web 类或含浏览器步骤的用例**，评审表「名称」列须含 **`{产品} > {页面/Tab} > {功能点}`**，与 `testcase-skills/UI精简` 段头、截图目录一致。

| 规则 | 说明 |
|------|------|
| 分隔符 | 使用半角 ` > `（空格+大于号+空格） |
| H4 标题 | 可短，如 `#### L-01 商品列表默认展示` |
| 评审表「名称」 | 写全路径，如 `秒杀财务 > 商品列表 > 默认展示在售商品` |
| 纯 API 用例 | 可用 `秒杀财务 > API > 登录鉴权` 或接口语义路径 |
| 与 UI 精简对齐 | 路径须能对应 `### [图] xxx · 秒杀财务 > …` |
| **有侧栏菜单时** | 第一段与**侧栏顶级菜单**一致，中间段与 Tab/子菜单一致，如 `秒杀财务 > 商品管理 > 商品列表` |
| **无侧栏（单页 Web）** | 用页面名即可，如 `秒杀财务 > 登录 > 正确凭证` |
| **路由驱动 SPA** | 可与 `screenshot-skills/全站截图` 路由清单 / `--crawl-menu` 目录名对齐 |

检查 7 亦称「菜单/页面路径」：有控制台侧栏时按**菜单层级**写；纯 Web 页按**页面路径**写，均须含 ` > `。

**秒杀示例**

| 编号 | H4 标题（可短） | 评审表「名称」（须全） |
|------|----------------|------------------------|
| L-01 | 商品列表默认展示 | 秒杀财务 > 商品列表 > 默认展示 |
| L-02 | 正确凭证登录 | 秒杀财务 > 登录 > 正确凭证进入商品列表 |
| V-03 | 重复用户名注册 | 秒杀财务 > 注册 > 重复用户名失败 |

**反例**：评审表名称仅写「登录成功」「商品列表」——缺少 ` > ` 路径，Step 6 检查 7 不通过。

## 6. 可选：JSON 入库结构

与测试平台对接时，每条用例可导出为：

```json
{
  "case_id": "L-01",
  "name": "在售列表仅含在售商品",
  "priority": "P0",
  "type": "regression",
  "tags": ["products", "list", "status"],
  "preconditions": "库中同时在售与已下架商品",
  "test_steps": [
    {"step": "打开商品列表", "result": "仅返回在售商品 ID"}
  ],
  "requirement_ref": "浏览在售商品列表",
  "status": "active"
}
```

`test_steps` 每项仅 `step` + `result`，**不得**使用 `expected_result` 键名。

## 7. 专业版交付要点（本包默认）

| 项 | 要求 |
|----|------|
| Step 0～6 | 全流程执行 |
| 通用覆盖矩阵 | **全表扫，触发行必有点或待澄清** |
| 用例编号 | **必填** |
| 评审表 | **必填** |
| 矩阵自检表 | **必填** |
| 待澄清清单 | **文末汇总** |
| OpenAPI 叠加 | 有契约时 **建议必做** H 维 |
