# 核心流程测试写法

> 示例业务：**秒杀财务系统**（`seckill_finance_system`）。流程拆分见 `core_flows.md`。

当 func_list 或 Step 0 产出 **「核心流程」** 章节时，按本章生成 **流程测试** 块（位于「核心流程测试」章节）。

---

## 1. 铁律

| 规则 | 说明 |
|------|------|
| 一条流程 = 一个 `### 流程N` 块 | 不要拆成多个无关用例 |
| 结构对齐 | 树形缩进与 func_list **一致** |
| 粒度 | 中等（约 10～15 主节点），非逐点击 |
| 业务目标单一 | 不同目标拆不同流程（见 `core_flows.md`） |

---

## 2. 标题格式

```markdown
## 核心流程测试

### 流程1：customer 参与进行中秒杀并下单成功
- 浏览在售商品列表（匿名 GET /api/products）
  - 登录获得 JWT
    - 选择 ACTIVE 活动与商品
      - POST 秒杀下单
        - 订单创建成功且 Redis 库存扣减
```

可选编号：`F-01` 对应 `### 流程1`。

---

## 3. 与详细功能点的分工

| 放在核心流程 | 放在详细功能点 |
|--------------|----------------|
| 主路径 Happy Path | 字段级校验、边界、权限边角 |
| 主分支（成功/明确失败） | 404、空列表、非法参数 |
| 端到端连贯步骤 | 单接口契约补充 |

**不要** 在流程里写「password 第 5、6 个字符」级细节；放到 V- 检查点。

---

## 4. 流程内可含的分支

- 主成功路径（必写）  
- PRD 强调的失败分支（如活动未开始、库存不足、超限购）  
- **不要** 把「admin 建活动 + customer 下单 + 财务记账」合并为一条巨型流程  

---

## 5. Step 6 对照

- [ ] 流程数量与 func_list 一致  
- [ ] 缩进层级一致  
- [ ] 术语与 PRD 一致（UPCOMING/ACTIVE/ENDED、admin/customer、pending 订单等）  
- [ ] 每条流程能映射到 F-xx 编号（专业版）  
- [ ] 无与本项目无关的领域示例（如 KYC、Waitlist）

---

## 6. 示例片段

```markdown
### 流程2：管理员新增商品且触发秒杀准备
- 管理员登录（POST /api/auth/login，admin）
  - POST /api/products 填写名称、常规价、秒杀库存为 10
    - 创建成功，商品为在售
      - POST .../prepare-stock 预热 Redis
        - 预热成功，status 接口可见 Redis 库存
      - Redis 不可用
        - 返回明确错误，不误导为预热成功
```
