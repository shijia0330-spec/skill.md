# 测试用例层级模式

> 层级示例以 **秒杀财务系统** 模块命名（认证、商品、秒杀、财务）。

## 原则

- **清晰**：易浏览
- **简洁**：无多余嵌套
- **合理**：分组符合测试执行习惯
- **平衡**：不过平也不过深（建议 ≤4 级标题）

## 三级结构（最常用）

```
## 功能模块 (H2)
### 测试场景 (H3)
#### 检查点 (H4)
```

**适用**：多数功能测试。

```markdown
## 用户登录
### 凭据正确
#### admin 账号登录成功
- username=admin、password=admin123，POST /api/auth/login 返回 200 且 JWT 可用于 Profile
```

## 二级结构（简单功能）

```
## 功能模块 (H2)
### 检查点 (H3)
```

**适用**：检查点 <10、无需场景分组。

```markdown
## 匿名访问商品列表
### GET /api/products 无需 Token
- 未登录请求返回 200，body 为在售商品数组
```

## 四级结构（复杂功能）

```
## 功能模块 (H2)
### 子模块 (H3)
#### 场景 (H4)
##### 检查点 (H5)
```

**适用**：跨多页面、多子流程的大模块（如「秒杀活动管理 + 预热 + 下单」）。

```markdown
## 秒杀功能
### 活动管理
#### 创建活动
##### 合法时间窗保存成功
- admin 提交 name、start、end，POST /api/seckill/activities 返回 201
```

## 决策树

```
功能点是否 >15 且需场景分组？
├─ 否 → 是否 <10 个检查点？
│        ├─ 是 → 2 级
│        └─ 否 → 3 级
└─ 是 → 是否有明确子模块？
         ├─ 是 → 4 级
         └─ 否 → 3 级
```

## 反模式

- [FAIL] 为单个检查点套 4 层空壳标题
- [FAIL] 所有项目一律 4 级
- [FAIL] 「测试用例 → 用例1 → 步骤1」无业务语义的分组
