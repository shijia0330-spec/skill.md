# 用例评审 — 上线前最后搂一眼

批量生成或大批量改动之后，**执行自动化或交给业务之前**，建议过一道评审：查漏、改措辞、把优先级捋顺，输出一份大家认的「最终集」。零星一条草稿不影响主线的可以偷懒不搞。

---

## 啥时候值得开会评审

- 发布窗口临近，或审计要留痕  
- 需求一改牵动一串用例  
- 已经闻到异味：步骤说不清、标签乱、critical 满天飞

单条草案、不影响发布范围的，可以不正式评审。

---

## 评审什么

| 检查项 | 关注什么 | 常见问题 |
|--------|----------|----------|
| RAG 摘要 | Step 0a 是否执行、来源是否标注 | 缺「知识库检索摘要」、RAG 补充点无出处 |
| 覆盖度 | 需求是否都覆盖了 | 漏了异常流程、没测边界值 |
| 准确性 | 预期结果对不对 | 写"成功"但没说怎么算成功 |
| 可执行性 | 别人能不能照着做 | 缺账号、缺测试数据 |
| 可维护性 | 标签和模块是否一致 | 同一功能分散在不同模块 |
| 优先级 | critical 是不是太多了 | 全标 critical 等于没有优先级 |

## 与生成 Skill 对齐

生成阶段已在 `testcase-skills/生成/references/universal_coverage_matrix.md` 做过矩阵扫描，并输出文末「通用覆盖矩阵自检」表。

评审时：

1. 复核矩阵打勾表是否如实（触发行是否真有点或 T-xx 待澄清）  
2. 对本清单做 **加强复核**（尤其安全/性能/并发等生成阶段可能仅占位项）  
3. 发布前以评审 Skill 输出为 **最终依据**

一页清单：`references/seckill_finance_review_checklist.md`。

---

## 覆盖度检查清单

逐项核对，不要走过场：

**功能覆盖**：
- [ ] 正向流程（Happy Path）是否覆盖
- [ ] 反向流程（异常处理）是否覆盖
- [ ] 边界值（最大/最小/临界）是否覆盖

**数据覆盖**：
- [ ] 空值测试（必填为空、null、空字符串）
- [ ] 超长输入（超过字段限制）
- [ ] 特殊字符（HTML 标签、SQL 关键字、转义字符）
- [ ] 编码问题（中文、emoji、全角字符）
- [ ] 格式验证（邮箱、电话、URL 等格式错误）

**状态覆盖**：
- [ ] 状态机转换（每个合法状态跳转）
- [ ] 非法状态转换（不允许的跳转是否被拒绝）
- [ ] 并发操作（同时修改同一资源）
- [ ] 幂等性（重复操作结果一致）

**集成覆盖**：
- [ ] 跨模块数据传递（上游变更影响下游）
- [ ] 异步回调（延迟、重试、最终一致性）
- [ ] 第三方依赖异常（外部服务不可用时的处理）

**非功能覆盖**：
- [ ] 性能（响应时间、并发能力）
- [ ] 安全（认证绕过、越权、注入攻击）
- [ ] 兼容性（多浏览器、多版本）

---

## 评审输出

1. **问题清单**：用例 ID、问题类型、建议动作（改写/拆分/废弃）
2. **合并后的用例集**：去重、统一术语、标记版本
3. （可选）通过 API 回填到测试平台

---

## 评审方法

- 用风险矩阵对照：影响范围 × 发生概率
- 有依赖的用例要求明确写 `preconditions`，或者拆成多条
- BDD 用例检查 `feature`、`scenario`、`background` 是否互补而不是重复

---

## 和「生成」的关系

**生成**负责多写；**评审**负责挑毛病、去冗余、提升质量。两者分工不同，不能互换。

---

```markdown
## Review-2026-05-06

  - id: TC-8840

ssot_tag: suite/member-v3.2-final
```

## 问题分级

| 级别 | 说明 | 处理方式 |
|------|------|----------|
| 阻塞级 | 用例无法执行或结果不可判定 | 必须修改 |
| 严重级 | 预期结果与业务规则不符 | 建议修改 |
| 一般级 | 格式或标签不规范 | 可择期修改 |

---

## 注意事项

1. **客观评判**：根据事实和规范，不要主观判断
2. **建议具体**：改进建议要可操作，别只说"不够好"
3. **优先级排序**：按严重程度排列问题
4. **标准一致**：同一批用例用同一套标准评审
5. **及时反馈**：发现问题尽快反馈，不要等全部评审完
6. **必须合并**：评审完成后必须输出完整用例集
7. **唯一依据**：完整用例集是后续执行的唯一依据，不能分散在多个文件
