# 压测规划

根据分析结果，设计压测场景 + 并发模型 + 数据策略。

## 触发条件

当用户提到以下关键词时使用：压测场景、并发模型、阶梯、参数化、数据策略。

## 做 / 不做

| 做 | 不做 |
|----|------|
| 设计压测场景（冒烟/基线/负载/压力/稳定性） | 直接生成脚本（走执行/SKILL.md） |
| 配置并发模型（用户数、爬坡、持续时间） | 执行压测（走执行/SKILL.md） |

## 压测场景设计

| 场景 | 目的 | 并发 | 持续时间 | 通过标准 |
|------|------|------|----------|----------|
| 冒烟 | 验证脚本正确性 | 1-5 | 1-2 min | 无报错 |
| 基线 | 单用户响应基准 | 1 | 3-5 min | P95 < 200ms |
| 负载 | 预期并发表现 | 50-200 | 5-15 min | P95 < 500ms, 错误率 < 1% |
| 压力 | 找瓶颈点 | 递增 | 直到报错 | 定位瓶颈 |
| 稳定性 | 长时间无泄漏 | 50-100 | 30min-24h | 无内存泄漏 |

## 并发模型

### 阶梯模型（推荐）

```
用户数
 200 |           +--------- 保持
     |      +----+
 100 | +----+
     |+
   0 |+-------------> 时间
     30s    5min    10min
```

### 配置参数

| 参数 | 说明 | 示例 |
|------|------|------|
| 起始用户 | 初始并发 | 10 |
| 爬坡时长 | 升到目标的时间 | 30s |
| 目标用户 | 最大并发 | 200 |
| 保持时长 | 目标并发持续时间 | 5min |
| 下降时长 | 回零时间 | 10s |

### JMeter 线程组配置示例

```
线程组:
  - 线程数: 200
  - Ramp-Up: 30 秒
  - 循环: 无限（调度器控制）
  - 调度器:
    - 持续时间: 300 秒
    - 延迟: 0 秒
```

### k6 stages 配置示例

```javascript
export const options = {
  stages: [
    { duration: '30s', target: 10 },   // 爬坡到 10
    { duration: '2m', target: 50 },    // 爬坡到 50
    { duration: '5m', target: 200 },   // 爬坡到 200
    { duration: '30s', target: 0 },    // 下降
  ],
};
```

## 数据策略

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| 固定数据 | 简单接口 | 所有用户用同一套数据 |
| CSV 参数化 | 登录/下单 | 每个用户不同账号/商品 |
| 动态生成 | 注册/发帖 | 每次请求生成新数据 |
| 混合模式 | 复杂场景 | 读操作用固定，写操作用动态 |

### 多用户 CSV 压测（与 data_factory 对齐）

规划输出须明确：

| 项 | 约定 |
|----|------|
| 账号数 N | `data_factory.users.count` ≥ 目标并发 |
| CSV 列 | `username, password`（明文密码，非 hash） |
| 引擎并发 | JMeter `threads` = N；k6 `concurrent` = N |
| CSV 配置 | `ignore_first_line: true`，`recycle: false` |
| 压测后 | `data_factory --cleanup` |

造数入口：`templates/data_factory.md` → JMeter `jmeter_test.md` / k6 `perf_test_k6_multiuser.md`

## 输出

输出 `压测规划_<项目>_<日期>.md`，包含场景表 + 并发配置 + 数据策略 + **账号数 N**。

**交给执行环节时**：未指定引擎则默认 **k6**（见 `load-testing/执行/SKILL.md`）；并发配置优先写 k6 `stages` 示例。
